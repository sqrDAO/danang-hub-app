## 2. Review of the week's changes

- **#249 / #259 / #254 / #268 / #270 (MCP booking server)**: correct.
  - **Tokens.** `functions/mcpTokens.js` stores only SHA-256 hashes. A member has one token, which expires after 90 days. Each request reserves a slot in a 60-per-minute counter inside a transaction. `requireUser` rechecks on every call that the account is not disabled and that its email is verified, and it exempts legacy profiles by the document's `createTime`, which a client cannot forge.
  - **Bookings.** `functions/mcpBookings.js` rechecks the token inside every write transaction. It reuses `computeBookingAvailability` through a transactional `readQuery`, serializes MCP creates on each amenity with a lock document, makes `requestId` idempotent, and limits cancel to the member's own pending bookings outside a plan.
  - **Rules.** `firestore.rules` blocks clients and admins from setting or changing `source`, and `test/firestore-mcp.rules.test.js` covers this.
  - **401 logging (#268).** The log records the header's shape and never the token.
  - **Hosting rewrite (#270).** `/mcp` is served through a Hosting rewrite with `Cache-Control: no-store`.
- **#208 / #247 (import an event from a link)**:
  - **Allowlist.** Hosts must match the allowlist exactly. HTTPS is required, ports and credentials in the URL are rejected, and every redirect is checked again by hand.
  - **Page fetch.** The fetch has an 8 s timeout and a 1 MB cap on the body.
  - **Rate limit and cover image.** A server-only counter allows 10 imports an hour per account (`importRateLimits` is `false` in the rules). The browser downloads the cover only from the three CDN hosts on the allowlist, with `redirect: 'error'`.

## 3. Findings

### M1 — `sendBookingConfirmation` runs on every booking but only logs

`functions/index.js:2285` is an `onDocumentCreated("bookings/{bookingId}")` trigger. It reads the amenity and then only calls `console.log`, and its email work is still a `TODO` (`:2298`). Each booking create pays for one invocation, one read and one log line, with nothing visible to the member. That includes every MCP booking and every day of a desk plan, so one 20-day fixed-desk plan costs 20 invocations. #206 removed the preference read but kept the stub. **Needs a human decision**: delete the trigger, or implement the email to the verified address only, skipping plan days. Issue: [#272](https://github.com/sqrDAO/danang-hub-app/issues/272).
