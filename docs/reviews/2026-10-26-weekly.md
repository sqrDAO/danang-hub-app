## 3. Findings

### M1 — Legacy Event Hall bookings are no longer cleaned up
Before #109, approving an event created a `bookings` doc (`eventId` set, status `approved`) and edit/reject cancelled it. That code is gone (`functions/index.js` `editOwnEvent`, `reviewEvent`), but nothing migrated existing docs. Any event approved before the change keeps an active booking that blocks the hall; if the organizer later edits or the admin rejects the event, the booking stays active and keeps blocking that slot. Not verifiable from the repo (needs prod data). Spec: [`todo.legacy-event-bookings-cleanup.md`](../backlog/todo.legacy-event-bookings-cleanup.md).

### L1 — Hub hours for events are client-side only
Server-side `getEventSpaceValidationError` was removed, so `editOwnEvent` / event creation accept any `requestedAmenityId` and date; only `validateEventSpaceTime` in the form enforces hours. This is consistent with the "advisory" invariant and the product decision in #109, so no spec — noted so it is a conscious gap.
